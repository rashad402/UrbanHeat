# Web — What-If Urban Heat Mitigation Simulator

Interactive ward-level simulator for Kochi (plan §12).

## Current: `simulator.html` (self-contained)

A single-file simulator using **MapLibre GL JS** (Mapbox-compatible API, no token needed).
It renders all 77 Kochi wards as a choropleth over real Landsat LST and lets you apply
cool roofs / greening / tree canopy per ward (or city-wide) with an instant ΔT cooling map.

**Run it** (needs a server so the relative data file loads — don't open via file://):

```bash
python -m http.server 8765 --directory web
# then open http://localhost:8765/simulator.html
```

Data: `ward_data.js` (generated by `scripts/build_ward_stats.py` from the pixel dataset) sets
`window.WARD_DATA` (per-ward geometry + mean LST/NDVI/albedo) and `window.CLIMATE`. Regenerate:

```bash
python scripts/build_ward_stats.py
```

### The ΔT model is a PREVIEW

The current cooling estimate is a **first-order surface-energy-balance stand-in**, not the trained
PINN: raising albedo cuts absorbed shortwave, adding vegetation adds latent cooling, each scaled by
the ward's built-up share and the restoring term `4εσT³ + ρcp/r_ah`, clamped to published tropical
ranges. **Swap in the PINN** by replacing `deltaT()` in `simulator.html` with a call to the trained
model's `/whatif` API (see plan §11) — the inputs (per-ward NDVI, albedo, climate) are the same.

## `simulator_live.html` — real satellite imagery + real 30 m LST

The "real product" slice: a **Sentinel-2 true-colour image** of Kochi with the **actual 30 m Landsat
LST** blended on top, and **click-anywhere queries** at an arbitrary radius (default 50 m) that return
the real mean LST and a preview ΔT for exactly those pixels. Proves the model works at pixel granularity.

The scene is rendered **server-side by Earth Engine and embedded as data URIs** (single `<img>` each,
no slippy-map library, no external tiles). This was a deliberate choice after WebGL/tile map libraries
(MapLibre, Leaflet) failed to render reliably in constrained webviews — a static image always paints and
the tab never hangs on tile requests. Trade-off: no pan/zoom (fixed city view). Click position maps
linearly to lon/lat over the returned bounds.

It needs the backend (GEE auth) and cannot be a published Artifact (that sandbox blocks external images):

```bash
uvicorn api.live_demo:app --port 8000
# then open http://localhost:8000/simulator_live.html
```

`api/live_demo.py` builds a dry-season median composite, serves its LST as tiles (`/api/config`),
and answers point/area queries (`/api/query`) by sampling GEE over a buffer and applying the same
SEB preview. Replace `seb_delta_t` with the trained PINN when ready.

## Later: Next.js + Mapbox port (optional)

If a richer app is wanted (routing, auth, Mapbox basemaps), port `simulator.html` into a Next.js app:

```bash
cd web && npx create-next-app@latest . --ts --app && npm install maplibre-gl
```

API contract for the PINN backend (plan §3):
`POST /whatif` → `{ ward_ids:[...], intervention:{ type, ndvi_delta?, albedo_set? } }`
returns `{ ward_id: { t_base, t_new, delta_t } }`.
